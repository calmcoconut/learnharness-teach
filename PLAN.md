# learnharness-teach — implementation plan

A portable Agent Skill that runs the LearnHarness teaching loop — probe, plan, teach,
practice, graph close — inside any agent harness that can read a folder, run `python3`
and ask the user a question.

Derived from the LearnHarness app (`/Users/alejandrodiaz/Documents/projects/learnharness`)
and a 36-decision design interview recorded in that repo at
`docs/grill-learnharness-teach.md`.

**Status:** design frozen. This document is the build contract.

---

## 1. What this is, and what it is not

**Is:** one installable skill. Copy the folder into `.claude/skills/learnharness-teach/`
or `.agents/skills/learnharness-teach/` and any of Claude Code, Codex CLI, Antigravity or
pi can teach a full session and leave a durable knowledge graph behind.

**Is not:** the app. No Electron, no Next, no HTTP server, no MCP server, no API keys
handled by us, no model selection, no UI. The harness supplies all of that.

**Non-negotiables carried over from the app's design:**

- Teaching measures before it teaches. The probe is never skipped.
- One reasoning step at a time, one check per step.
- The answer key is committed before the question is asked.
- Position is *derived*, never stored. There is no done-ledger.
- Graph extraction is tree-blind: it never sees the plan.

## 2. Hard requirements

| Requirement | Reason |
|---|---|
| `scripts/*.py` import only the standard library | zero-install folder copy |
| `scripts/*.py` parse under Python 3.10 (`ast.parse(..., feature_version=(3,10))`) | declared floor |
| `SKILL.md` body < 500 lines | Agent Skills spec; enforced by the app's sibling suite |
| frontmatter uses spec fields only: `name`, `description`, `license`, `compatibility` | Claude-Code-only fields hard-fail on other hosts |
| `name:` equals the folder name (`learnharness-teach`) | spec |
| no network access from scripts | portability and safety |
| scripts set `sys.dont_write_bytecode = True` before importing helpers | no `__pycache__` in the user's project |
| every script resolves its own directory, never the CWD | CWD independence |
| tests may use any dev dependency; shipped scripts may not | suite never ships |

`LICENSE` is AGPL-3.0-only and must stay byte-identical to the app's `LICENSE`.

## 4. Record contract

Everything lives under `.learnharness/` at the project root, committed to git.
One learner per record. The skill never reads or writes the app's data directory.

```
.learnharness/
├── graph/
│   ├── nodes.jsonl
│   ├── chains.jsonl
│   └── format.json
└── sessions/
    └── <session-id>/
        ├── session.jsonl     # canonical, append-only
        └── session.md        # generated by `session.py render`
```

`format.json`:

```json
{
	"version": 1,
	"writer": "learnharness-teach/0.1"
}
```

`version` must be written. Readers refuse `version > 1`. The app ignores `writer`.

### 4.1 Session ids

Format: `lh_` + 8 lowercase base36 characters, e.g. `lh_k3m9x2qp`.
Validated against `^lh_[a-z0-9]{8}$` before any path is built.

### 4.2 Event log

One JSON object per line, terminated by `\n`. Append-only; the file is never rewritten
except by `session.py render` writing `session.md` (a different file).

Every event carries:

| field | type | meaning |
|---|---|---|
| `seq` | int ≥ 1 | 1-based, strictly increasing, no gaps |
| `at` | string | ISO-8601 UTC, e.g. `2026-01-14T09:31:07Z` |
| `type` | string | one of the nine below |

**The nine event types.**

```jsonc
// 1. session_start — always seq 1, always exactly one
{"seq":1,"at":"…","type":"session_start","kind":"teach","goal":"understand why entropy always increases"}

// 2. check_posed — the key is committed here, before the learner sees the question
{"seq":2,"at":"…","type":"check_posed","node":null,"question":"What does 'reversible' mean for a process?",
 "options":["It can be run backwards with no net change to the universe","It happens slowly","It is isothermal"],
 "correct":[0],"key":"A reversible process leaves no net change in the universe; that is the definition, not a rate property."}

// 3. answer — closes the check named by check_seq
{"seq":3,"at":"…","type":"answer","check_seq":2,"selection":[0],"correct":true,
 "confidence":4,"trace":"No net change anywhere means it can be undone exactly."}

// 4. probe_concluded — at most one per session, refused while a check is open
{"seq":4,"at":"…","type":"probe_concluded",
 "strands":[{"strand":"entropy as counting","assessment":"holds; can explain multiplicity without prompting"}],
 "summary":"Strong on counting, no working notion of irreversibility."}

// 5. plan_set — revision 1 is the initial plan, 2+ are revisions
{"seq":5,"at":"…","type":"plan_set","revision":1,
 "nodes":[{"id":"irreversible","title":"Irreversibility","summary":"why some processes have a direction"}],
 "edges":[{"from":"counting","to":"irreversible"}]}

// 6. step_closed — a teaching step finished
{"seq":6,"at":"…","type":"step_closed","node":"irreversible","outcome":"held"}

// 7. practice_problem — practice sessions only; modelSolution is committed up front
{"seq":2,"at":"…","type":"practice_problem","statement":"…","mode":"recall",
 "target":["irreversible"],"modelSolution":"…"}

// 8. practice_concluded — practice sessions only
{"seq":3,"at":"…","type":"practice_concluded","outcome":"solvedWithHints","verdict":"…",
 "rung":"R2","missClass":"cue","retest":true,
 "work":"optional: what the learner actually wrote"}

// 9. session_closed — terminal; at most one
{"seq":7,"at":"…","type":"session_closed","nodes_written":12,"chains_written":4}
```

`kind` ∈ `{"teach","practice"}`. `node` is `null` during the probe phase and a plan node id
during teaching. `correct` on an `answer` is computed by the agent, not by a script — there
is no client to grade.

### 4.3 Derivations

All derived from the log, never stored:

| value | rule |
|---|---|
| `phase` | `practice` kind → `practice`; else no `probe_concluded` → `probe`; else no `check_posed` with non-null `node` → `plan`; else `teach`. `session_closed` present → `closed`. |
| `open check` | the last `check_posed` whose `seq` is not referenced by any `answer.check_seq`. At most one may be open. |
| `current node` | `node` of the most recent `check_posed` with non-null `node`, else `null` |
| `visited nodes` | every non-null `node` in an *earlier* `check_posed` |
| `plan` | the `plan_set` with the highest `revision` |
| `closed` | a `session_closed` event exists |

Note the phase rule mirrors the app: the plan phase ends at the first *node-tagged check*,
not at `plan_set`. Authoring a plan does not by itself leave the plan phase.

### 4.4 Graph ledgers

App-compatible. One JSON object per line.

```jsonc
// nodes.jsonl
{"id":"n_a1b2c3d4e5f6","name":"Entropy is a count","statement":"Entropy is the logarithm of the number of microstates.",
 "aliases":[],"createdAt":"…","provenance":[{"chatId":"lh_k3m9x2qp","messageId":"4"}]}

// chains.jsonl
{"id":"arg_a1b2c3d4e5f6","premises":["n_…"],"conclusion":"n_…",
 "provenance":[{"chatId":"lh_k3m9x2qp","messageId":"4"}],"createdAt":"…"}
```

**Writer obligations** — these are not stylistic, they come from the app's guards:

1. `aliases` and `provenance` must always be present arrays, even when empty.
   The app drops any line missing either (`src/store/graph.ts:97-109`).
2. Every chain premise and conclusion must resolve to a node id that exists in
   `nodes.jsonl` after the merge, or the app drops the chain from its derived view
   (`src/core/graph.ts:481`).
3. `provenance.chatId` is `lh_<session>`, `messageId` is the `seq` of the originating event.
4. Node ids are `n_` + 12 lowercase hex; chain ids are `arg_` + 12 lowercase hex.
   Ids are derived deterministically from the statement / chain key so a re-run is idempotent.
5. Merging follows the app's law: a later line with an existing id appends its `statement`
   and `aliases` to the accumulated `aliases` and unions `provenance`; `name` and
   `createdAt` from later lines are ignored.
6. Malformed lines are *skipped by the app silently*. `graph_write.py` therefore validates
   every record it writes and refuses rather than emitting something that would vanish.

## 5. Script contracts

All scripts: `python3 scripts/<name>.py [global opts] <command> [opts]`.
Global options precede the command. Every script exits 0 on success, 1 on refusal,
and prints human-readable output to stdout (or `--format json` where offered).

### 5.1 `session.py`

| command | behaviour |
|---|---|
| `init --goal TEXT [--kind teach\|practice]` | create `.learnharness/sessions/<id>/`, write `session_start`; prints the id |
| `check --session ID --question TEXT (--key TEXT\|--key-file PATH) [--node ID] [--options a,b,c | --options-file PATH] [--correct 0,2]` | refuse if a check is open, if `--node` is unknown, or if no key given; append `check_posed` |
| `answer --session ID (--select 0,2\|--text TEXT) --confidence 1-5 --trace TEXT` | refuse if no check is open; append `answer` with computed `correct` |
| `conclude-probe --session ID (--strands FILE\|--strands-json JSON) [--summary TEXT]` | refuse if a check is open or a conclusion exists; append `probe_concluded` |
| `plan-set --session ID --plan FILE\|-` | validate via `plan.py` first; refuse on invalid; append `plan_set` with next revision |
| `step-close --session ID --node ID [--outcome held\|partial\|missed]` | refuse unknown node; append `step_closed` |
| `practice-problem --session ID --problem FILE\|-` | practice kind only; append `practice_problem` |
| `practice-concluded --session ID --result FILE\|-` | practice kind only; append `practice_concluded` |
| `close --session ID [--nodes-written N] [--chains-written M]` | append `session_closed`, optionally carrying what the close step merged; refused if already closed |
| `state --session ID` | print the compact derived summary (§6) |
| `render --session ID [--write]` | emit `session.md` to stdout, or write it with `--write` |
| `list` | list sessions with id, kind, phase, goal, node count |

`--correct` indices are 0-based positions in `--options`. Omitting `--options` makes the
check free-recall; then `--correct` is omitted and correctness is the agent's judgement,
recorded on `answer`.

### 5.2 `plan.py`

`plan.py validate --plan FILE|-` → reads `{nodes:[{id,title,summary?}],edges:[{from,to}]}`.

Refuses (exit 1, `{ok:false,"error":…}`) on: empty nodes; id not matching
`^[a-z0-9]+([_-][a-z0-9]+)*$`; duplicate id; empty title; edge referencing an unknown id;
self-loop; duplicate edge; cycle. Warns (does not refuse) above 15 nodes.
Success prints `{ok:true,"nodeIds":[…],"warnings":[…]}`.

### 5.3 `graph_write.py`

`graph_write.py merge --session ID --proposals FILE|-`

Proposal input uses local refs so the agent never invents global ids:

```json
{"nodes":[{"ref":"a","statement":"…","name":"…","aliases":["…"]}],
 "chains":[{"premises":["a"],"conclusion":"b"}]}
```

Behaviour: resolve each ref to an existing node (matching `statement` or an alias) or mint
a new id; validate every chain endpoint resolves; append node lines and chain lines;
return `{ok:true,"nodes":N,"chains":M,"reused":R}`. Refuses on unknown refs, empty
premises, duplicate chain keys, or a chain whose conclusion equals its sole premise.

Idempotent: re-running the same proposals appends only link lines for new provenance and
writes no duplicate chains.

### 5.4 `graph.py`

`graph.py [--data-dir PATH] [--format markdown|json] <command>`

| command | behaviour |
|---|---|
| `sessions` | sessions appearing in provenance, with node counts |
| `propositions [--session ID]` | node list, optionally filtered to a birth session |
| `find QUERY` | substring match, `*` is the only wildcard |
| `chains [--node ID]` | chains, optionally those containing a node |
| `export --to PATH` | copy `nodes.jsonl` and `chains.jsonl` into `PATH`, stamp `format.json` version 1, leave other files untouched |

`export` is the supported route into the app's data directory. It must not delete or
rewrite the app's `sessions.jsonl`, `coverage.jsonl`, `sources.json` or `positions.json`.

### 5.5 `verify.py`

`verify.py [--session ID]` → audits and exits 1 if anything is wrong:

- more than one open check
- a `check_posed` with no key
- an `answer` whose `check_seq` does not exist or is already answered
- a second `probe_concluded`, or a `probe_concluded` while a check was open
- a `plan_set` that fails `plan.py` validation
- a `step_closed` for a node absent from the current plan
- chain endpoints that do not resolve
- node lines missing `aliases` or `provenance`
- `format.json` version above 1

## 6. `session.py state` output

The only thing the agent reads on resume. Bounded by design.

```
session  lh_k3m9x2qp   kind teach   phase teach   closed no
goal     understand why entropy always increases
plan     revision 1, 6 nodes, 7 edges   (warn: above 15 nodes)
current  irreversible
visited  counting, multiplicity
open     none
last     irreversible — correct (confidence 4)
         "No net change anywhere means it can be undone exactly."
next     4 of 6 nodes untouched
```

`--format json` emits the same fields as an object.

## 7. Enforcement summary

| rule | enforcement |
|---|---|
| one open check at a time | **hard** — `check` and `conclude-probe` refuse |
| key committed before the question | **hard** — `check` refuses without `--key` |
| plan is a valid DAG | **hard** — `plan.py` refuses |
| `probe_concluded` at most once | **hard** — `conclude-probe` refuses |
| ≤8 probe strands / ≤15 plan nodes / ≤20 steps | advisory warning only |
| writes confined to `.learnharness/` | **none** — trusted |
| python3 present | **hard** — scripts are the product |

The advisory rows are deliberate. There is no path guard and no confinement assertion;
that is a recorded decision, not an oversight.

## 8. Phases and references

| phase | reference | what it does |
|---|---|---|
| probe | `references/probe.md` | measure where understanding ends along each dependency strand; one question at a time; no plan-node field exists, so it cannot reason about a plan |
| plan | `references/plan.md` | author a dependency map from measured starting points to the goal; node/edge list; rendered once |
| teach | `references/teach.md` | one reasoning step at a time, each hanging off something already held; one check per step; predict → explain → check |
| practice | `references/practice.md` | varied problems sampled from the graph; pre-committed model solution; R0–R5 hint ladder; miss classification |
| close | `references/graph.md` | tree-blind extraction → audit → merge, run in a fresh invocation with the session log as its only input |

`references/methodology.md` holds the theory and is loaded on demand, not by default.

**Voice rule:** `probe.md` and `teach.md` are separate prompts with a hard mode switch.
The probe reference must not be loaded during teaching and vice versa. This preserves the
property that the prober has no plan-node field at all.

### Review round 1

An adversarial review of the first pushed commit found 2 critical, 7 high, 12 medium and 6
low defects. All are fixed. The ones worth remembering, because they are the class of bug
that tests written by the author do not catch:

- **The documented install was broken.** Every reference said `python3 scripts/session.py`,
  but the install puts the skill in a skills directory, so `scripts/` is never at the project
  root. A model following the docs literally failed on the first command. The docs guard
  could not catch it because it only checked that the file existed somewhere in the repo.
  Shipped commands are now written as `python3 <skill>/scripts/…` and a test fails on any
  bare path.
- **`export` destroyed the app's graph.** It overwrote an existing `nodes.jsonl` and
  downgraded a version-9 `format.json` to version 1 — silent, irreversible data loss in the
  exact command the README gives users. It also wrote nothing yet still stamped the
  destination when the source record was missing. Export now refuses a newer destination
  stamp, refuses a non-empty destination without `--replace`, verifies the source exists, and
  refuses malformed source lines.
- **The probe could be skipped entirely**, and teaching could begin before it concluded,
  despite the probe being called non-negotiable.
- **Practice sessions could write propositions**, defeating the reason practice is a separate
  session kind.
- **Advisory size limits failed the audit**, so a legitimate 9-strand probe could not close
  or export.
- **Concurrent appends produced duplicate `seq`** and several open checks, because the seq
  was computed outside any lock.

The suite grew from 145 to 220 tests. Every fix has a regression test, and the guards that
mattered most — install-path and export-safety — are the two the original suite structurally
could not see.

## 10. Risks carried into the build

1. **Prompt fidelity.** 488 lines of app fragments name app tools and assume a UI.
   Rewriting them changes pedagogy and no script test catches a regression.
   Mitigation: `tests/fixtures/golden/` transcripts plus `rubric.md`, reviewed by hand.
2. **Trust posture.** No path guard, no confinement assertion, advisory-only sizes.
   A wrong path or a runaway plan has nothing mechanical standing in the way.
3. **Silent data loss.** The app drops malformed ledger lines without error. Every write
   must be validated by `graph_write.py`, and `verify.py` must be run before `export`.
4. **App-side rewrites.** The app rewrites ledgers on session deletion and chain
   simplification. Imported data is not protected from a later rewrite.
5. **Antigravity has no system-prompt channel.** `SKILL.md` must be self-sufficient there.
6. **Codex's `request_user_input` is mode-gated** and reported to drift to free text.
7. **No compaction.** Bounded resume via `session.py state` is the mitigation, and it is
   the reason resume never reads the full log.
